# PROB 训练与评估流程中的数据统计与可视化梳理

## 1. 目标与范围

本文档聚焦两条主分支：

- 训练分支（train）：从 epoch/step 训练，到训练统计落盘与训练曲线生成。
- 评估分支（eval）：从推理评估、开放世界指标汇总，到在线可视化与离线案例可视化流水线。

涉及核心代码：

- main_open_world.py
- engine.py
- visual/train_writer.py
- visual/eval_visualizer.py
- visual/metrics_plotter.py
- datasets/open_world_eval.py
- configs/EVAL/S_OWODB/CH3_Full_VIS_PIPELINE_SVG.sh
- tools/plot_uod_manifold_3d_svg.py
- tools/mine_representative_cases_svg.py
- tools/render_mined_cases_svg.py
- tools/organize_rendered_cases_svg.py


## 2. 主流程入口与分支切换

### 2.1 主入口

主入口在 main_open_world.py 的 main(args)。

关键分流逻辑：

- 当 --eval 为真：直接进入 evaluate(...) 评估分支，执行一次评估并退出。
- 当 --eval 为假：进入训练循环 for epoch in range(...)，每轮先 train_one_epoch(...)，再按策略触发 evaluate(...)。

评估触发策略（训练态）：

- 首轮与次轮会触发评估。
- 逢 lr_drop 轮触发。
- 按 eval_every 周期触发。
- 最后一轮触发。


## 3. 训练分支：统计与可视化

## 3.1 训练循环中的统计收集路径

调用链如下：

main_open_world.py
-> train_one_epoch(...)（engine.py）
-> write_train_step_artifacts(...)（visual/train_writer.py）

其中 train_one_epoch(...) 的统计来源主要有三层：

- 损失层：criterion 输出的 loss_dict。
- 优化层：lr、grad_norm。
- 查询层：匹配/未匹配查询、伪正例候选与接受率、已知/未知概率统计。


### 3.2 step 级统计（train/metrics_step.jsonl）

由 write_train_step_artifacts(...) 逐 step 落盘，典型字段包括：

- 基本训练状态：
  - train/loss/total
  - train/optim/lr
  - train/optim/grad_norm
  - train/quality/class_error
- 原始与加权损失：
  - train/loss_raw/*
  - train/loss_weighted/*
- 伪标签选择效率：
  - train/pseudo/selection_ratio
  - train/pseudo/accept_ratio
- 查询分布统计：
  - train/query_stats/matched_objectness_prob_mean
  - train/query_stats/unmatched_objectness_prob_mean
  - train/query_stats/unknown_probability_mean
  - train/query_stats/max_known_class_probability_mean
  - train/query_stats/odqe_gate_mean
  - train/query_stats/odqe_gate_mean_layer_*

此外每隔固定间隔还会向 TensorBoard 写直方图（如 objectness_energy、unknown_logit、unknown_probability）。


### 3.3 epoch 级统计（train/metrics_epoch.jsonl）

在 main_open_world.py 每轮训练结束后汇总并写入，核心内容：

- train_total_loss、train_lr、train_grad_norm、train_class_error
- 基础检测损失：CE、bbox、GIoU（raw/weighted）
- UOD 相关损失：loss_obj_ll、loss_unk_known、loss_obj_pseudo、loss_obj_neg、loss_unk_pseudo、loss_decorr 等
- 伪标签挖掘计数：
  - num_selected_pseudo_positive_queries
  - num_selected_reliable_background_queries
  - num_pseudo_positive_candidates
  - num_classification_ignored_queries
- 伪标签效率比率：
  - pseudo_positive_selection_ratio
  - pseudo_positive_accept_ratio


### 3.4 训练可视化产物（train/plots）

由 refresh_metric_plots(...) 触发，实际由 visual/metrics_plotter.py 生成 SVG 曲线图，主要包括：

- 训练 epoch 曲线：
  - training_total_loss.svg
  - training_base_loss_components.svg
  - training_open_world_loss_components.svg
  - pseudo_mining_counts.svg
  - pseudo_mining_efficiency.svg
- 训练 step 曲线：
  - step_total_loss.svg
  - step_base_losses.svg
  - step_open_world_losses.svg
  - step_query_score_statistics.svg
  - step_pseudo_mining_statistics.svg
  - step_auxiliary_loss_trends.svg

TensorBoard 方面：

- train/tensorboard/run_时间戳 目录下保存标量、直方图和部分图像。


## 4. 评估分支：统计与可视化

## 4.1 评估循环中的统计收集路径

调用链如下：

main_open_world.py
-> evaluate(...)（engine.py）
-> OWEvaluator（datasets/open_world_eval.py）
-> eval_visualizer（visual/eval_visualizer.py）

evaluate(...) 内部主要工作：

- 模型前向与 postprocess（bbox）
- evaluator.update(...) 累积预测
- collect_eval_visual_stats(...) 收集查询级统计与特征采样
- save_eval_qualitative_cases(...) 生成定性案例图
- evaluator.accumulate() + evaluator.summarize() 得到开放世界指标
- compute_branch_correlation_metrics(...) 计算分支相关性
- finalize_eval_visualizations(...) 汇总导出统计文件与图像


### 4.2 开放世界评估指标（open_world_metrics）

来自 datasets/open_world_eval.py 的 summarize()，常见指标：

- WI（Wilderness Impact）
- AOSA（Absolute Open-Set Error，对外可被标记为 A-OSE）
- CK_AP50 / CK_P50 / CK_R50（当前引入类）
- K_AP50 / K_P50 / K_R50（全部已知类）
- U_AP50 / U_P50 / U_R50（未知类）
- 可选：PK_AP50 / PK_P50 / PK_R50（历史已知类）

此外 engine.evaluate(...) 会把分支相关性指标并入 open_world_metrics：

- corr_global_obj_unk
- corr_global_obj_cls
- corr_global_unk_cls
- corr_fg_obj_unk
- corr_fg_obj_cls
- corr_fg_unk_cls


### 4.3 评估落盘文件

- eval/metrics_epoch.jsonl
  - 每个被触发评估的 epoch 记录 open_world_metrics。
- eval/bbox_eval/latest.pth（以及部分 epoch 快照）
  - COCO bbox evaluator 的原始 eval 结构。


### 4.4 在线评估可视化输出（eval/visualizations/epoch_xxxx）

由 visual/eval_visualizer.py 直接生成，目录结构通常包含：

- final/
  - 每图的 panel（预测对比、已知/未知拆分、错误案例）
  - contact sheet 汇总图
- debug/
  - pseudo mining 多阶段可视化 panel
- stats/
  - query_statistics.csv
  - feature_samples.npz
  - error_case_summary.csv
  - query_probability_histograms.svg
  - query_relationship_scatter.svg
  - branch_correlation_heatmap.svg
  - layer_prediction_summary.svg
  - feature_embedding_pca.svg
  - feature_embedding_tsne.svg

说明：

- query_statistics.csv 存每个采样 query 的 objectness/unknown/max_known/group。
- feature_samples.npz 存三分支特征样本（objectness/knownness/classification）及分组标签。
- 图像类输出既可离线查看，也可部分写入 TensorBoard。


## 5. 离线评估可视化流水线（S_OWODB CH3 SVG）

对应脚本：configs/EVAL/S_OWODB/CH3_Full_VIS_PIPELINE_SVG.sh

该脚本将“官方 eval 输出”与“额外案例可视化”串联为流水线：

1) run_stage_eval

- 用 --eval + --viz 跑 main_open_world.py。
- 产出 eval/visualizations/epoch_xxxx 下在线统计与图像。

2) run_stage_offline_visualization

- tools.plot_uod_manifold_3d_svg
  - 输入：stats/query_statistics.csv 与 stats/feature_samples.npz
  - 输出：stats/standalone_3d/*.svg（3D 流形与分数空间切片）
- tools.mine_representative_cases_svg
  - 挖掘代表案例，输出：infer/representative_cases/
    - representative_case_manifest.json
    - known_top_cases.csv / unknown_top_cases.csv / odqe_salient_top_cases.csv
    - 各类别 contact_sheet.svg
- tools.render_mined_cases_svg
  - 根据 manifest 渲染 query 级图件（sampling/gate/joint/trajectory）
  - 输出：infer/rendered_cases/
    - 按 image/query 分目录保存 SVG
    - render_manifest.json
- tools.organize_rendered_cases_svg
  - 把分散图件组织为图集
  - 输出：infer/figure_atlas/
    - boards/*.svg
    - atlas_manifest.json
    - INDEX.md


## 6. 训练与评估分支中的统计/可视化职责分工

- main_open_world.py
  - 负责流程编排、epoch 级汇总、JSONL 追加、plot 刷新调度。
- engine.py
  - 负责每 step/每 batch 的核心统计调用与评估可视化调用。
- visual/train_writer.py
  - 负责 step 级训练记录、TensorBoard 标量/直方图写入。
- visual/eval_visualizer.py
  - 负责评估期 query 统计采样、定性图、错误案例、统计图与特征降维图。
- visual/metrics_plotter.py
  - 负责基于 JSONL 的训练/评估曲线图再生成。
- datasets/open_world_eval.py
  - 负责开放世界指标计算与汇总（WI/AOSA/K_AP50/U_R50 等）。


## 7. 建议的排查顺序（实操）

当你需要追踪“某个指标/图是怎么来的”，建议顺序如下：

1. 先在 main_open_world.py 确认当前运行是 eval-only 还是 train+periodic-eval。
2. 再看 engine.py 对应函数（train_one_epoch 或 evaluate）是否调用了统计/可视化入口。
3. 到 visual/train_writer.py 或 visual/eval_visualizer.py 对照字段名与图文件名。
4. 若是开放世界主指标（WI、AOSA、K_AP50、U_R50 等），直接看 datasets/open_world_eval.py。
5. 若是论文图集/案例图，沿着 CH3_Full_VIS_PIPELINE_SVG.sh -> tools/*.py 追踪。
